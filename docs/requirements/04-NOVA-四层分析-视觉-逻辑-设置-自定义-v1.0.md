# NOVA LAB 四层分析：视觉 / 逻辑 / 设置 / 自定义

分析对象：`https://novalive.cn/lab/`  
分析目的：拆出「呈现什么」「为什么这样判断」「哪些能配」「哪些能让用户自己定」  
状态：需求分析，不改代码

---

## 总览

NOVA LAB 可以拆成四层：

```text
视觉呈现层
  用户第一眼看到什么、按什么顺序看

背后逻辑层
  这些结果是怎么算出来、怎么升级、怎么失效的

设置层
  系统/策略/数据/风控的固定参数

自定义层
  用户能改什么、不能改什么
```

对应到我们的 MOSS CORE：

```text
视觉呈现 = NEURAL 星环 + 结果卡片
背后逻辑 = 行情/信号/阶段/风控引擎
设置     = 管理员/策略参数
自定义   = 用户自己的监控范围和展示方式
```

---

# 第一部分：视觉呈现

## 1. 呈现原则

NOVA 的视觉不是“数据大屏”，而是**结论先行、证据跟随**：

```text
第一层：现在市场怎么样
第二层：现在哪些币值得看
第三层：为什么是它
第四层：历史验证过没有
```

它没有一上来铺 500 个币，而是先给结论，再让用户下钻。

---

## 2. 页面结构

### 2.1 顶部

- 页面标题：NOVA 实验室 / 策略监控
- 副标题：实时信号、MM 观察、跨所 OI、聪明钱代理、历史回测
- 状态：主策略是否正常、最后更新时间
- 关键数字：
  - 扫描合约数
  - 核验交易所数
  - 当前最高评分
  - 最高评分币种

### 2.2 市场状态卡

这是首屏最重要的一块：

```text
大行情势头    [弱势]    49.3
BTC 24h +0.24%
BTC 流动性 正常
市场流动性 18.6/20
数据完整度 90%
置信度 高
```

下面展开：

- 四个因子及得分
- 四档风控表
- 研究建议
- 执行说明

视觉上它是**横向结论条**，不是普通表格。

### 2.3 实时信号区

- 过滤：全部 / 开仓信号 / 重点候选 / 初筛观察 / 外部持仓 / 领先
- 候选卡：
  - 排名
  - 币种
  - 阶段标签
  - 选择理由
  - 参考价 / 开仓信号价
  - 本次推荐时间
  - 首次进入筛选时间
  - 阶段变化
  - 策略分
  - 5 分钟涨幅 / 开仓后涨幅
  - 1 分钟成交额
  - 全网 OI
  - 交易所 OI 条
  - 公开交易员成本

视觉重点是**阶段标签 + 策略分 + 理由**，不是 K 线。

### 2.4 单币详情

点击候选后打开详情：

- 策略为什么选中
- 评分明细
- 盘面参考
- 10x / 20x 风控参考
- 全网持仓核验
- 交易所明细表
- 全网 OI 历史
- 公开交易员开仓成本
- 代币历史价格与阶段
- 监控结果分析

这一层是**证据层**，用表格、数字、少量折线，不用花哨图表。

### 2.5 MM 观察池

- 已知 MM 项目
- 反复横跳项目
- 三阶段适配度
- 历史入场价
- 价格 / 成交 / OI / 资金费率
- 成本代理
- 持仓快增 / 快退
- 手动加入观察池

### 2.6 低市值区

- 低市值十币表
- 排名、币种、现价、流通市值、24h、主策略阶段、研究动作
- 低市值进入初筛时弹独立提醒

### 2.7 历史区

- 上一周涨幅榜与允许开仓信号
- 历史回测归档
- 纸面交易（公开页隐藏）
- 研究归档

### 2.8 视觉语义

NOVA 用颜色表达阶段：

| 语义 | 颜色 |
|---|---|
| 开仓 / 通过 / 上涨 | 绿 |
| 观察 / 候选 / 中性 | 黄 / 琥珀 |
| 风险 / 失败 / 下跌 | 红 |
| 无数据 / 未达标 | 灰 |

我们 550C 不能直接照搬绿色，要换成：

| 语义 | 550C |
|---|---|
| 最高优先级 / 开仓 | 亮金 `#FFC043` |
| 重点候选 | 金 `#E8A020` |
| 初筛观察 | 暗金 / 灰金 |
| 风险 / 失效 | 红 `#FF1A12` |
| 正常 / 数据完整 | 白 `#F2F0E8` |

## 3. 交互

NOVA 的交互很克制：

- 过滤标签切换
- 点击候选打开详情
- 详情里看评分、OI、交易所、历史
- 加入观察池
- 手动回测
- 页面 5 秒自动刷新

没有复杂拖拽，没有多级弹窗。

### 我们建议保留的交互

- 点击左侧信号 → 中央星环和左下证据卡切换
- 点击阶段标签 → 过滤队列
- 点击交易所 OI 条 → 展开交易所明细
- 点击“为什么” → 展开评分明细
- 新事件 → 粒子提醒 + 事件流

### 不建议的交互

- 不要把所有数据塞进一个长页面
- 不要让用户自己找“哪个币最重要”
- 不要把回测、纸面、实盘混在首屏

# 第二部分：背后逻辑

## 1. 数据链路

```text
交易所行情
  ↓
标准化
  ↓
流动性预筛
  ↓
短周期动量评分
  ↓
三级信号晋级
  ↓
全网 OI / 交易所核验
  ↓
大盘状态
  ↓
事件与提醒
  ↓
前端结果
```

NOVA 的页面只是最后一步，真正核心在前面。

---

## 2. 市场状态逻辑

总分权重：

```text
市场广度 30%
BTC/ETH 与活跃币趋势 25%
流动性 20%
信号强度 15%
有效 OI 10%
```

状态分档：

| 档位 | 分数 | 对已有仓位的含义 |
|---|---|---|
| 强势 | 75–100 | 给利润更多空间 |
| 稳定 | 55–74.9 | 正常分批止盈 |
| 弱势 | 35–54.9 | 10% 内优先锁盈 |
| 差 | 0–34.9 | 优先保本、锁盈、退出 |

关键点：

- 四档只影响已有仓位风控
- 不改变开仓条件
- 大盘差的时候，不是“停止所有开仓”，而是“已有仓位先保护”

---

## 3. 信号评分逻辑

从接口和页面可以还原出评分结构：

```text
基础分 55
+ 1 分钟动量 × 8，上限 18
+ 3 分钟动量 × 5，上限 16
+ 5 分钟动量 × 3.5，上限 14
+ 15 分钟动量 × 1.2，上限 8
+ 24 小时位置，最高 8
+ 24 小时成交额，最高 8
+ 距短线高点回撤，最高 5
+ 微观盘口，最高 2.5
```

核心不是公式本身，而是：

> **每个分数都能解释，每个阶段都有明确门槛。**

---

## 4. 三级信号逻辑

| 阶段 | 通常分数 | 24h 涨幅 | 成交额 | 回撤 | 短时动量 |
|---|---|---|---|---|---|
| 初筛观察 | ≥72 | 1–80% | ≥3M | ≤14% | 1m≥0.25% 或 3m≥0.5% 或 5m≥0.8% |
| 重点候选 | ≥76 | 2–65% | ≥5M | 页面未固定 | 1m≥0.35% 或 3m≥0.7% 或 5m≥1.0% |
| 开仓信号 | ≥86 | 3–55% | ≥8M | ≤8% | 1m≥0.55% 或 3m≥1.0% 或 5m≥1.35% |

特殊模板可以从初筛直接跳到开仓，但条件更严格。

### 晋级逻辑

```text
初筛观察
  → 分数、成交、回撤、动量继续满足
重点候选
  → 分数、成交、回撤、动量继续满足
开仓信号
```

不是分数高就自动开仓，还要：

- 交易资格
- 入场点确认
- 金额与倍数
- 止盈止损
- 账户熔断

---

## 5. OI / MM 逻辑

### 持仓快增

```text
全网 OI 5 分钟 +5%
或 15 分钟 +10%
且名义持仓净增 ≥100,000 USDT
交易所覆盖口径稳定
```

### 持仓快退

方向相反：

```text
5 分钟 -5%
或 15 分钟 -10%
且净减 ≥100,000 USDT
```

### 重要解释

- OI 增加可能来自多仓、空仓、对冲仓
- 不能单独判断方向
- 只能作为“资金方向代理”
- 必须结合价格、主动买卖、资金费率
- 公开交易员成本只作参考

---

## 6. 数据质量逻辑

NOVA 在结果里明确展示：

- 数据完整度
- 置信度
- 数据新鲜度
- 交易所覆盖数
- OI 数据质量警告
- 未入选原因
- 失效原因

这一点非常重要：

> **没有数据时不能编造，不能用 0 冒充缺失。**

---

## 7. 刷新逻辑

```text
网页刷新 5 秒
主策略扫描 30 秒
全网核验 60 秒
```

我们的软件应显示每一块数据的“最后更新时间”，过期要变灰/报警。

---

  "regime": {

# 第三部分：设置

设置要分三层，不能混在一起。

## 1. 系统设置（管理员）

- 数据源
- API Key
- 交易所覆盖
- 扫描频率
- 数据保留
- 代理/网络
- 日志级别
- 版本/发布通道

## 2. 策略设置（策略负责人）

- 市场状态权重
- 四档分数边界
- 三级信号门槛
- 评分项权重/上限
- 成交额门槛
- 回撤门槛
- 短时动量门槛
- OI 快增/快退阈值
- 低市值筛选条件
- 10x / 20x 风控参数
- 回测区间与手续费
- 是否允许纸面/实盘

这些参数不能给普通用户随便改，否则结果不可比。

## 3. 用户设置（监控使用者）

- 监控哪些币
- 是否只看指定币
- 告警方式
- 声音
- 窗口/托盘
- 显示模块
- 主题
- 刷新频率
- 默认打开页面

## 4. 推荐的设置表

| 设置项 | 归属 | 默认 | 影响 |
|---|---|---|---|
| 数据源 | 系统 | Binance Futures | 全局 |
| 扫描间隔 | 系统 | 30s | 信号新鲜度 |
| 全网 OI 间隔 | 系统 | 60s | OI 结果 |
| 市场广度权重 | 策略 | 30% | 大盘状态 |
| 开仓分数 | 策略 | 86 | 信号数量 |
| 重点候选分数 | 策略 | 76 | 候选数量 |
| 初筛分数 | 策略 | 72 | 观察数量 |
| OI 5m 阈值 | 策略 | 5% | MM 提醒 |
| OI 15m 阈值 | 策略 | 10% | MM 提醒 |
| 告警方式 | 用户 | 应用内 | 提醒 |
| 监控范围 | 用户 | 全市场 | 队列内容 |
| 默认页面 | 用户 | 总览 | 打开体验 |

# 第四部分：自定义

自定义也分三层，不能越权。

## 1. 展示自定义

用户可以改：

- 左侧队列显示哪些阶段
- 是否显示 MM 池
- 是否显示低市值
- 底部六格显示哪些指标
- 事件流密度
- 主题/配色
- 窗口大小
- 是否常驻托盘

不能改：

- 策略分数
- 阶段门槛
- 市场状态权重

## 2. 监控范围自定义

这是最重要的自定义：

### 模式 A：全市场候选

像 NOVA 一样，系统扫描全市场，用户看结果。

### 模式 B：指定币观察

用户只添加自己关心的币：

```text
BTC、ETH、SOL、WIF、SEI……
```

系统只对这些币做：

- 异动监控
- 阶段判断
- OI 快增/快退
- 提醒

### 模式 C：混合

全市场信号 + 指定币观察池。

我建议第一版支持：

```text
全市场候选（只读）
+ 用户自选观察池（可添加/删除）
```

这样不会一上来就做成“全市场 500 币大表”。

## 3. 告警自定义

用户可配置：

- 只提醒开仓信号
- 提醒重点候选
- 提醒初筛
- 提醒 OI 快增/快退
- 提醒低市值
- 提醒大盘转弱
- 静音时段
- 声音/桌面通知/Webhook

## 4. 风控自定义

用户可配置：

- 10x / 20x 显示
- 保证金止损
- 利润峰值回撤
- 最大同时持仓
- 单币最大仓位

但不能让用户改：

- 市场状态算法
- 信号评分算法
- 历史回测口径

# 我们产品该怎么落

## 第一版建议

### 视觉

- 顶部市场状态条
- 左侧三级信号队列
- 中央星环锁定最高优先级
- 左下证据卡

- 市场状态
- 三级信号
- 评分明细
- 数据新鲜度
- 事件流
- 先不接纸面账户/自动下单

- 只做系统设置 + 用户告警设置

### 自定义

- 自选观察池
- 告警开关
- 显示模块开关

## 第二版

- MM 观察池

- 阶段历史
- 回测归档

## 第三版

- 纸面账户
- 多账户

# 需要你拍板的地方

1. 我们的产品是 **全市场候选**，还是 **指定币观察**，还是两者都有？
2. 策略参数是只有你能改，还是未来给用户改？
3. 纸面账户和回测进不进主界面？
4. 告警是只做应用内，还是要 Windows 通知/声音/Webhook？

这四点确定后，我再出：

- 首屏线框
- 组件字段表
- 设置页结构
- 自定义规则
- 开发任务拆分

在此之前不动代码。
