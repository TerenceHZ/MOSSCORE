# 单代币三窗口内容定义 v1.0

文档状态：学习稿，暂不开发  
整理时间：2026-11-02  
适用对象：MOSS CORE 中每一个代币  
核心约束：一个代币只能有三个内容窗口，不再增加第四个。

---

## 1. 结论

一个代币固定三个窗口：

```text
NOW      当前信号
PROOF    证据与多签
TRACE    历史监控
```

对应关系：

| 窗口 | 一句话定位 | 默认打开方式 |
|---|---|---|
| NOW | 现在发生了什么，为什么值得看 | 点击代币行 / 当前卡 |
| PROOF | 凭什么相信，链上多签和行情证据是什么 | 点击多签标记 / 多签金额 |
| TRACE | 这是新信号还是旧信号，之前发生过什么 | 点击左侧模块 / 历史标签 |

三个窗口都只在主窗口内的同一个弹窗里切换，不新开软件窗口。

---

## 2. 为什么是三个，不是四个

一个代币的决策链只有三段：

```text
现在值不值得看
→ 凭什么相信
→ 之前是不是已经看过
```

再多一个窗口，就会开始重复：

- 行情窗口重复六格
- 证据窗口重复 OI
- 历史窗口重复分数
- 设置窗口又把告警拆走

所以固定三个，其他内容只能作为这三个窗口里的折叠区、链接或空状态，不再单独开窗。

---

## 3. 窗口一：NOW · 当前信号

### 3.1 回答的问题

```text
现在是什么阶段？
为什么现在提醒？
位置高不高？
风险在哪里？
```

### 3.2 必须放的内容

| 区块 | 内容 |
|---|---|
| 标题 | 币种、自选/导入、当前阶段、分数、最后更新时间 |
| 六格 | 24H / 5M / 1M QV / 全网 OI / 回撤 / 策略分 |
| 结论 | 一句话说明为什么现在看 |
| 触发原因 | 动量、成交额、OI、回撤、多签等命中的条件 |
| 位置 | 24H 高低位、距高点、北京日涨跌 |
| 风险 | 10x / 20x 止损参考、失效条件、数据缺失项 |
| 数据 | 数据源、更新时间、新鲜度、是否过期 |

### 3.3 不应该放的内容

- 完整多签历史列表
- 完整历史触发时间线
- 所有 1/5/15/30/60 周期明细
- 盘口逐档、逐笔成交
- 资金费率的完整历史

这些放在 PROOF 或 TRACE 里，避免 NOW 变成大杂烩。

### 3.4 视觉

- 自选：暗金主值、暖金强调
- 导入：灰白主值、低亮强调
- 数据缺失：灰色“待核验”
- 数据过期：灰色或暗红“已过期”
- 新鲜态：15 分钟边框/背景流光，之后恢复普通态

---

## 4. 窗口二：PROOF · 证据与多签

### 4.1 回答的问题

```text
这个信号有没有链上或行情证据？
多签累计是多少？
数据是不是可信、是不是过期？
```

### 4.2 必须放的内容

#### A. 多签证明

| 字段 | 说明 |
|---|---|
| 累计额度 | 从第一条记录开始只加不减 |
| 记录笔数 | 累计记录数量 |
| 本次新增 | 最近一条新增金额 |
| 币种 / 链 | 代币与链 |
| 多签地址 | 地址及标签（如可得） |
| 签名门槛 | 例如 2/3、3/5 |
| 代币数量 | 本次新增对应数量 |
| 当时 USD | 记录时点的美元价值 |
| 占流通比例 | 如可得，缺失写“待核验” |
| 数据来源 | 链上 / 数据商 / 公开页 |
| 验证时间 | 最后一次核验时间 |
| 证据链接 | 区块浏览器或数据源链接 |

口径必须写清楚：

```text
只记录多签额度新增
累计全部历史
只加不减
不追踪流入流出
不扣减
不算当前余额
不判断资金方向
```

#### B. 行情证据

- OI 5M / 15M / 30M / 1H 变化
- 成交额 / 均量比
- 盘口深度 / 滑点
- 资金费率
- 持续资金 30s / 60s
- 聪明钱 / 参与者（数据可用时）

这些数据不重复六格主值，只展示“支撑/不支撑”的证据。

#### C. 数据质量

```text
哪些字段是实时的
哪些是延迟的
哪些缺失
哪些已过期
```

### 4.3 不应该放的内容

- 当前六格的重复大数字
- 完整历史触发时间线
- 交易建议或自动下单按钮

### 4.4 多签触发口径

```text
本次新增 ≥ 200,000 USD
或
累计额度首次达到/超过 200,000 USD
```

播报格式：

```text
本次新增 +1,000,000
累计额度 1,200,000
记录 2 笔
```

## 5. 窗口三：TRACE · 历史监控

### 5.1 回答的问题

```text
这是新信号还是旧信号？
之前升级/降级过吗？
上次触发是什么时候？
OI 和多签之前有没有异动？
```

### 5.2 必须放的内容

| 区块 | 内容 |
|---|---|
| 统计 | 今日/近 3 天/近 7 天/全部触发次数 |
| 时间线 | 时间、触发类型、阶段、分数、原因 |
| 阶段变化 | 初筛 → 候选 → 开仓，或降级 |
| OI 事件 | 快增 / 快退 |
| 多签事件 | 累计首次过阈值 / 单笔大额 |
| 重新进入 | 离开后再次进入监控 |
| 数据 | 触发时快照、数据源、缺失项 |

### 5.3 只记录这些事件

- 进入初筛观察
- 升级重点候选
- 升级开仓信号
- 降级
- OI 快增 / 快退
- 多签累计达到阈值
- 低市值进入初筛
- 重新进入监控

不记录每一次普通扫描。

### 5.4 不应该放的内容

- 当前六格完整重复
- 全部原始行情 K 线
- 逐笔成交
- 没有触发的日常扫描日志

### 5.5 交互

- 今天 / 近 3 天 / 近 7 天 / 全部
- 点击某条事件 → 回到该时点的 NOW 快照
- 默认滚到最新
- 可导出

## 6. 三个窗口的数据归属

| 数据 | NOW | PROOF | TRACE |
|---|---|---|---|
| 当前价格/24H | 主 | 引用 | 事件时点 |
| 5M 动量 | 主 | 引用 | 事件时点 |
| 1M QV | 主 | 引用 | 事件时点 |
| 全网 OI | 主 | 5M/15M 证据 | 事件时点 |
| 回撤 | 主 | — | 事件时点 |
| 策略分/阶段 | 主 | — | 事件时点 |
| 多签累计 | 摘要 | 主 | 事件 |
| 多签记录 | — | 主 | 事件 |
| 历史触发 | — | — | 主 |
| 盘口/资金费率 | 摘要 | 主 | — |
| 数据质量 | 摘要 | 主 | 事件 |

原则：

```text
NOW 放结论和当前值
PROOF 放证据和可信度
TRACE 放时间和变化
```

---

## 7. 打开路径

```text
点击左侧代币行
→ NOW

点击底部当前卡
→ NOW

点击多签标记 / 多签金额
→ PROOF

点击左侧模块标题
→ TRACE

点击右上多签窗口
→ PROOF 或按币种进入 PROOF

弹窗内部
→ 只在这三个窗口之间切换
```

---

## 8. 空状态

| 窗口 | 空状态 |
|---|---|
| NOW | 数据未齐，显示“待核验”，不生成假分数 |
| PROOF | 暂无多签记录，显示“—”，不写 0 |
| TRACE | 尚未触发，显示“暂无监控事件” |

---

## 9. 不做的事情

- 不新开第四个窗口
- 不把设置、告警、原始数据拆成新窗
- 不自动下单
- 不把多签解释成资金流入
- 不把“多签出现”直接写成“市值团队介入”
- 不在三个窗口之间重复展示同一组大数字

---

## 10. 一句话总结

**NOW 回答“为什么现在看”，PROOF 回答“凭什么相信”，TRACE 回答“是不是已经看过”。一个代币只保留这三个窗口，其他信息全部降级为区块、折叠或链接。**
